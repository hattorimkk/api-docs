# Get rule results
> Đường dẫn: API Reference > Automated Rules > Get rule results
Use this endpoint to get the execution results of rules based on the values of certain filters. 

## Request

**Endpoint** `https://business-api.tiktok.com/open_api/v1.3/optimizer/rule/result/list/`

**Method** GET

**Header**

| Field | Data Type | Description |
|---|---|---|
| Access-Token  **(Required)** | string | Authorized access token. For details, see [Authentication](doc:1738373164380162). |
| Content-Type  **(Required)** | string | Request message type ⏎ Allowed format: `"application/json"` |

**Parameters**

| Field | Data Type | Description |
|---|---|---|
| advertiser_id  **(Required)** | string | Advertiser ID |
| filtering | object | Filters |
| ↳ status | string | Status of rules. Enum values:  • `ON`: on. • `OFF`: off. • `DELETED`: deleted. |
| ↳ rule_info | string[] | Rule ids or rule names. |
| ↳ action | string | Filter by the action of the rule. Enum values: `TURN_ON`, `TURN_OFF`, `MESSAGE`, `DAILY_BUDGET`, `LIFERIME_BUDGET`, `BID` |
| ↳ time | string[] | An array of length two, which are the start datetime and the second one is the end datetime. It should be UTC+0 timezone. |
| ↳ data_dimension | string | Enum values: `CAMPAIGN`, `ADGROUP`,` AD`. |
| page | number | Current page number. Default: 1 |
| page_size | number | Page size. Default: 10 |
| lang | string | Language of the error messages. Enum values: `EN` (default value), `ZH`,` JA`. |

### Example
```JSON
// JSON
{
    "advertiser_id": "75960823018",
    "filters":[
        {
            "filter_type":"STATUS",
            "filter_input":["DELETED"]
        }
    ],
    "lang":"EN",
    "page":1,
    "page_size":100
}
```
## Response

| Field | Data Type | Description |
|---|---|---|
| code | number | Response code. For the complete list of response codes and descriptions, see [Appendix - Return Codes](doc:1737172488964097). |
| message | string | Response message. For details, see [Appendix - Return Codes](doc:1737172488964097). |

| ↳↳ page | number | Current page number. |
| ↳↳ page_size | number | Page size. |

| ↳↳ total_page | number | Total pages of results. |
| ↳ rules | object[] | List of rules |
| ↳↳ apply_objects | object[] | Objects that you want to apply the rules to. Objects can be campaigns, ad groups, or ads. |
| ↳↳↳ dimesion | string | Category of the object. Enum values: `CAMPAIGN`, `ADGROUP`, `AD`. |
| ↳↳↳ dimension_ids | string[] | IDs of the objects |
| ↳↳↳ pre_condition_type | string | Conditions to filter out objects that you do not want to include. | ↳↳↳ bind_type | string | Bind type of the rule. Enum values: `BIND`, `UNBIND` |
| ↳↳ conditions | object[] | Conditions |
| ↳↳↳ subject_type | string | Subjects that the condition will be based on. Enum values:  • `COST` • `DAILY_BUDGET_SPENDING_RATE` • `LIFETIME_BUDGET_SPENDING_RATE` • `IMPRESSION` • `CLICK` • `CONVERSION` • `CONVERSION_SKAN` • `CVR` • `CVR_SKAN` • `CPA` • `CPM` • `CPC` • `CTR` • `COST_PER_RESULT` • `RESULT` • `RESULT_RATE` • `BID_STRATEGY` • `OPTIMIZATION_GOAL` • `OBJECTIVE` • `NAME` • `DAYS_SINCE_CREATION` • `NO_CONDITION` • `ROAS_PURCHASE` • `ROAS_IMPRESSION_ADS` • `ROAS_PURCHASE_SKAN` • `ROAS_COMPLETE_PAYMENT` • `ROAS_PURCHASES_ONSITE` • `NOT_REAL_TIME_CPA` • `NOT_REAL_TIME_CONVERSION` • `NOT_REAL_TIME_CVR` |

| ↳↳↳ match_type | string | Operator to connect a condition with a value. Enum values:  • `GT` (greater than)  • `LT` (less than)  • `BETWEEN` • `MATCH` • `CONTAINS` • `NOT_CONTAINS` • `START_WITH` • `END_WITH` • `STRING_EQUAL` |
| ↳↳↳ values | string[] | Values for the condition. |
| ↳↳↳ calculation_type | string | Enum values:  • `ALL_OBJECTS` • `OF_EACH_OBJECT` |
| ↳↳ action | object[] | Actions to be taken when the condition is met |
| ↳↳↳ subject_type | string | Type of actions to take. Enum values: `TURN_ON`, `TURN_OFF`, `MESSAGE`, `DAILY_BUDGET`, `LIFERIME_BUDGET`, `BID` |
| ↳↳↳ action_type | string | Enum values: `INCREASE`, `DECREASE`, `ADJUST_TO` |
| ↳↳↳ value_type | string | Enum values: `EXACT`, `PERCENT` |
| ↳↳↳ value | object | When `action_type` is `INCREASE` or `DECREASE`, users can specify the maximum(if INCREASE) or minimum(if DECREASE) budget using `use_limit` and `limit`. When `action_type` is `ADJUST_TO`, no need to provide `use_limit` and `limit`. |
| ↳↳↳ frequency_info | object | Frequency settings. It can be used when the action `subject_type` is `DAILY_BUDGET`, `LIFERIME_BUDGET`, or `BID` |
| ↳↳↳↳ type | string | Enum: •  `ONLY_ONCE` •  `ONCE_IN_24_H` •  `ONCE_IN_48_H` •  `ONCE_IN_1_W` •  `CUSTOM` |
| ↳↳↳↳ custom_frequency_type | string | Custom frequency type. Valid only when `type` is `CUSTOM`. Enum: •  `N_MINTUE_Y_TIMES` •  `N_HOUR_Y_TIMES` •  `N_DAY_Y_TIMES` |
| ↳↳↳↳ time | number | It is the `N` in `custom_frequency_type` |
| ↳↳↳↳ count | number | It is the `Y` in `custom_frequency_type` |
| ↳↳ notification | object | Notification settings |
| ↳↳↳ notification_type | string | Notification type you need. Enum values:  • `TASK_FINISH`: Notification will be sent when the task is finished. This option is only for `MESSAGE` subject type. • `ANY_CHANGES`: If the `subject_type` for the action is not `MESSAGE` but you still want to receive emails, use this option. • `NOT_NOTIFICATION`: No notifications are needed. |
| ↳↳↳ email_setting | object | Email notification settings |
| ↳↳↳↳ notification_period | string | Enum values: • `EVERY_TIME` • `TIME_SCHEDULE`: notifications will be sent together around a specified time. |
| ↳↳↳↳ email_exec_time | string[] | Required when notification_period is`TIME_SCHEDULE`. Notification email sent time. For example, "12:00". |
| ↳↳↳↳ no_result_notification | boolean | It will be set as false by default if not provided, meaning no notification will be sent if there is no result. |
| ↳↳ rule_exec_info | object | Rule run settings |
| ↳↳↳ exec_time_type | string | When the rule will be run. Enum values:  • `PER_HALF_HOUR`: the rule will be run every half hour. • `CUSTOM`: the rule will be run at a customized time (specified in the `exec_time` field). • `HALF_HOUR_IN_SPECIFIC_TIME_PERIOD`: the rule will be run every 30 minutes during specified time range on specifed days during the week. • `SPECIFIC_TIME_ACCURATE_ONCE`: the rule will be run only once at a customized time (specified in the `exec_time` field). |
| ↳↳↳ exec_time | string | If `exec_time_type` is set to `CUSTOM` or `SPECIFIC_TIME_ACCURATE_ONCE`, use this field to specify the exact time when the rule will be run. ⏎ Format: ⏎ • "HH:MM" when `exec_time_type` is `CUSTOM`. For example: "12:00". • "YYYY-MM-DD HH:MM" when `exec_time_type` is `SPECIFIC_TIME_ACCURATE_ONCE`. For example: "2023-04-20 04:20". |
| ↳↳↳ time_period_info | object[] | Valid when `exec_time_type` is `HALF_HOUR_IN_SPECIFIC_TIME_PERIOD`. It has `start_time`, `end_time`, `date_type` and `num` to specify the time period information. |
| ↳↳↳↳ num | integers[] | Each number in the list represents the day in the week or month. • When `date_type` is `WEEK`, value range for this field is  [1, 7], meaning Monday to Sunday. • When `date_type` is `MONTH`, value range for this field is  [1, 28], meaning 1st day to the 28th day of the month. |
| ↳↳↳↳ start_time | string | Start time of this time period. For example, "12:00". |
| ↳↳↳↳ end_time | string | End time of this time period. For example, "12:00". |
| ↳↳↳↳ date_type | string | Type of date. Enum values: `DAY`, `WEEK`, `MONTH`. |
| ↳↳ last_check_result_summary | object | Information about the last rule run |
| ↳↳↳ check_datetime | string | Date and time when the rule was checked, in UTC+0 time zone |
| ↳↳↳ exec_datetime | string | Date and time when the rule was run, in UTC+0 time zone |
| ↳↳↳ change_success | number | Objects that have been changed |
| ↳↳↳ no_change | number | Objects that have not been changed |
| ↳↳↳ change_fail | number | Objects that failed to be changed |
| ↳↳↳ task_exec_id | string | Rule execution ID |
| ↳↳ rule_id | string | ID of the rule |
| ↳↳ name | string | Name of the rule |
| ↳↳ rule_status | string | Rule status. Enum values:  • `ON`: on. • `OFF`: off. • `DELETED`: deleted. |
| ↳↳ create_datetime | string | Date and time when the rule was created, in UTC+0 time zone |
