# Responses and errors
> Đường dẫn: Marketing API > Ad Measurement > Guides > Events API 2.0 > Responses and errors
## API response
Events API 2.0 returns a response with the following fields:
``` xtable
|Field{20%}|Data Type{20%}|Description{60%}|
|---|---|---|
|code |number|Response code. For the complete list of response codes and descriptions, see [Appendix-Return Code](doc:1737172488964097). |
|message|string|Response message. For details, see [Appendix - Return Codes](doc:1737172488964097).|
|request_id |string|The log ID of a request, which uniquely identifies the request.  |
|data |object|Returned data.<br>For a successful request,  this field will be an empty object (`{}`). <br>For a failed request, this field will not be returned.|
```
## API response codes 
For a full list of possible API response codes returned by TikTok API for Business, refer to [Appendix - Return Codes](doc:1737172488964097). 

### For successful calls
If the event is received successfully by TikTok, the API will return a response with `200` HTTP Status Code. The response body will contain an API response code (TikTok API for Business return code) of `0`. 

| Return code | HTTP Status Code | Description | Detail |
|---|---|---|---|
| 0 | 200 | Successful | Request succeeded. |

#### Example
```http
// curl
HTTP 1.1 200 OK
{
  "code": 0,
  "message": "OK",
  "request_id": "{{request_id}}",
  "data":{} 
}
```
### For failed calls
If the request fails, you will get a `4XX` or `5XX` HTTP Status Code. The response body will contain a corresponding return code and a message explaining the details about the failure. Check the `message` field in the response body for error details.

If multiple events are sent in the same API call, the `message` field will also indicate the index (zero-based) of the first invalid event. For example, the error message below suggests that the **third** event's `event_id` is not a valid string.

Below is a list of commonly seen errors for Events API 2.0:

| Return Code | HTTP Status Code | Error reason |
|---|---|---|
| 40001 | 400 | No permission. ⏎ You don't not have the necessary permission to operate the advertiser account. |
| 40002 | 400 | Invalid payload. ⏎ **Common causes**:  •  The payload is not a valid JSON. • Missing required field or wrong field type (for instance, passing in string when a number is required). • An unhashed value is used for a field (for instance, `email`) that requires SHA256 hashing • Sending too many events (>1000) in a single request. |
| 40100 | 401 | Too many requests (exceeded API quota limit). ⏎ **Common causes**:  • The rate limit for the endpoint (1,000 queries per second) has been reached, thus your request is throttled. |
| 40104 | 401 | Access token is empty. |

#### Example
```http
// curl
HTTP/1.1 400 Bad Request
{
  "code": 40002
  "message": "Invalid value for email: not a valid SHA256-hashed string."
  "request_id": "{{request_id}}"
}
```
