# Get started with Skill management
> Đường dẫn: Skill and MCP management > Get started with Skill management
Complete the prerequisites in this article before uploading your first Skill.

## Prerequisites
Before you can upload Skills to the TikTok for Business Developers portal, you must:
1. [Create a TikTok for Business account](slug:create-a-tiktok-for-business-account). This gives you access to the TikTok for Business ecosystem.
2. [Register as a developer](slug:register-as-a-developer). This unlocks the **My Agentic Hub** module and Skill upload capabilities.
> **Note:** 
> If you have previously used any TikTok API for Business endpoints, you already meet both prerequisites and can proceed directly to preparing your Skill file.

## Prepare an eligible Skill file
Before you upload a Skill, ensure your Skill file conforms to the platform's format and structure requirements. 

A well-structured file passes review faster and provides a better experience for agents consuming your instructions.

### File requirements

| Category | Requirement |
|---|---|
| Format | A `.zip` archive containing both a `SKILL.md` and a `README.md` file (case-sensitive). ⏎ The SKILL file must be placed directly at the archive root. |
| Size | Maximum file size: 50 MB (compressed). |
| Naming | Use only lowercase letters, numbers, and hyphens. Do not use spaces, uppercase letters, or special characters. ⏎ The name must be descriptive and action-oriented (for example, `launch-app-campaign`). Avoid generic names such as `skill1`. ⏎ .zip naming format: `Company name-skill goals-Version number` (English only). For subsequent updates, only change the version number. Example: `a3-company-budget-optimization-skill-v1` ⏎ The `name` field in the YAML frontmatter of your `SKILL.md` file must match the Skill Name you provide in the Skill upload form on the developer portal. |
| Frontmatter | Valid YAML format (delimited by `---`) with the `name` and `description` fields. ⏎ Must be followed by a Markdown body. |
| Description | Clearly states what the Skill does and when to use it. ⏎ Lead with the primary use case. ⏎ Recommended length: within 1,536 characters. |
| Body | Clear, actionable agent instructions. ⏎ Recommended length: 15,000 to 20,000 characters. ⏎ Place lengthy reference material in the `reference/` directory. |

### Package structure
Your Skill must be packaged as a .zip archive that follows a structured format designed for AI agent consumption.Structure your archive as follows:
```http
// curl
launch-app-campaign/
├── SKILL.md              # Main skill file (required)
├── README.md             # Documentation for human users (required)
├── reference/            # Supporting reference files (optional)
│   ├── optimization-rules.md
│   ├── benchmarks.json
│   └── templates/
│       └── report-template.md
├── scripts/              # Optional automation scripts (optional)
│   └── data-processing.py
└── config.json           # Optional configuration schema (optional)
```

**Component breakdown:**
- **SKILL.md**: Contains YAML frontmatter (metadata such as name, description, version, author, and permissions) followed by detailed instructions that guide the AI agent through your workflow.
- **README.md**: Documentation for human users explaining what the Skill does, its prerequisites, and how to use it. Like the SKILL.md file, this must be placed directly at the archive root (case-sensitive).
- **reference/**: Supplementary documents the agent can consult during execution, such as optimization rules, benchmark data, or report templates.
- **scripts/**: Executable scripts the agent can invoke to perform data processing, API calls, or other automated tasks.
- **config.json**: A schema that defines configurable parameters, allowing advertisers to customize Skill behavior without modifying the core instructions.

### Example SKILL.md
Below is a well-structured SKILL.md file showing valid YAML frontmatter followed by a Markdown body with clear, actionable instructions:

```http
// curl
---
name: "campaign-performance-optimizer"        # Skill name (required), must match the Skill Name field used when uploading the skill.
description: "Use this Skill when you need to evaluate campaign performance and take optimization actions. It analyzes performance data, identifies underperforming ad groups, and generates actionable recommendations."
version: "1.0.0"
author: "Developer Company Name"
use_case: "Ads Management"
permissions:
  - campaign_management
  - reporting_analytics
---

# Campaign Performance Optimizer

## Description
This Skill helps you monitor and optimize TikTok ad campaign performance. Provide a date range and target CPA, and the Skill will identify underperforming ad groups and suggest specific optimization actions.

## Process
1. Pull campaign performance data for the specified date range
2. Identify ad groups where CPA exceeds target by 20%+
3. Generate optimization recommendations
...
```

### Write an effective `description`
The `description` field is the single most important field. The agent uses it to decide whether the Skill is relevant. Write it to convey both the capability itself and the natural language expressions a user might use.

Good example:
```http
// curl
description: Launches a TikTok catalog ads campaign end to end. Use when the user wants product sales, catalog remarketing, or to promote a product feed.
```

Weak example (too vague to reliably match):
```http
// curl
description: Helps with ads.
```

### Write an effective body
- State **what to do**, not lengthy narratives about the process or rationale. Once loaded, the body stays in context, so every line is an ongoing cost.
- Keep `SKILL.md` within **15,000–20,000 characters**. Move longer reference material to supporting files.
- Include explicit **confirmation steps** before any write or budget-spending operations.
- Specify the **exact output format** you want (table, JSON, summary) to ensure consistent results.
- Handle empty results and error cases (If no data is returned, state so explicitly).

### README.md requirements
Every Skill package must include a `README.md` file that explains how the Skill is used in practice.

#### Required elements

| Element | Description |
|---|---|
| Project name and one-line summary | What it is and what problem it solves. |
| Quick Start | The simplest install and run example. |
| Target platform | Any platform restrictions (specify if applicable). ⏎ Target platforms include: ChatGPT, Claude, Gemini, etc. |
| Prerequisites / Dependencies | Runtime environment, permission requirements, dependencies, and whether any MCP or agent other than TikTok for Business MCP is used (if so, specify how). |
| Configuration | What is configurable and what the defaults are. |

#### Recommended elements

| Element | Description |
|---|---|
| Common errors and troubleshooting | How to self-diagnose when something goes wrong. |
| Limitations and caveats | Edge cases and known issues. |
| Contact information | Who maintains it and how to report issues. |
