# Create an audience by rule
> Đường dẫn: API Reference > Audience > Create an audience by rule
Use this endpoint to create an audience by rules. 

To create an audience, you need to specify a set of inclusion rules and optionally a set of exclusion rules. 

>**Note:**  •  Newly created audiences require at most 48 hours to be analyzed and processed before they become active.  • Use [/dmp/custom_audience/get/](doc:1739940507792385) to check the current status of an audience. Only 'available' (`is_valid` = `true`) audiences can be operated on. Upon expiration, the audience will become 'Unavailable' (`is_valid` =`false`), and get detached from any active campaign. • If a campaign has no targeting settings other than audience targeting, it will be paused.

 ## Comparing v1.2 and v1.3
 The following table outlines the differences between v1.2 and v1.3 endpoints. 
 
| Changes | v1.2 | v1.3 |
|---|---|---|
| Endpoint path | /v1.2/dmp/custom_audience/rule/create/ | /v1.3/dmp/custom_audience/rule/create/ |
| Request parameter data type | `advertiser_id`: number ⏎ `is_auto_refresh`: number | `advertiser_id`: string ⏎ `is_auto_refresh`: boolean |
| New request parameters | / | `retention_in_days` ⏎ `identity_id` ⏎ `identity_type` ⏎ `identity_authorized_bc_id` ⏎ `parameter_filters` (including all parameters within the object array) |
| Response parameter data type | `custom_audience_id`: number | `custom_audience_id`: string |

**Parameters**

| Field | Data Type | Description |
|---|---|---|
| advertiser_id  **(Required)** | string | Advertiser ID. |
| custom_audience_name  **(Required)** | string | Audience name. ⏎ Length limit: 128 characters. |

| audience_sub_type | string | Audience sub type, indicating the type of ads that the audience can be used. ⏎ Enum values:  • `NORMAL`: Audience for non-Reach & Frequency ads. •  `REACH_FREQUENCY`: Audience for Reach & Frequency ads. It can only be used in Reach & Frequency ads. Default value: `NORMAL`. |
| retention_in_days | integer | Number of days to retain the audience. ⏎ Value range: 1-365. ⏎ **Note**: • If this field is passed, the expiration date will be the specified number of retention days from the date when the audience was created. Any operations to the audience CANNOT reset the expiration date. • If this field is not passed, the expiration date will be 365 days from the last time the audience was applied to an active ad group or modified. Applying the audience to an active ad group or modifying the audience will reset the expiration date. To learn about the actions that will reset the expiration date, refer to the Help Center article [Audience Expiration Policy](https://ads.tiktok.com/help/article/audience-expiration-policy?redirected=2). |
| is_auto_refresh | boolean | Whether to turn on the audience auto-refresh function. ⏎ Supported values: `true`, `false`. ⏎ Default value: `true`. ⏎ If you enable this feature, your audience will automatically refresh to include the latest user data according to the lookback window you set. If you disable this feature, your audience will not automatically refresh. |
| identity_id {+Conditional} | string | Required when `audience_type` is `ENGAGEMENT_LIVE_VIDEO` or `ENGAGEMENT_ORGANIC_VIDEO`. ⏎ Identity ID. |
| identity_type {+Conditional} | string | Required when `audience_type` is `ENGAGEMENT_LIVE_VIDEO` or `ENGAGEMENT_ORGANIC_VIDEO`. ⏎ Identity type. ⏎ Enum values: `TT_USER`, `BC_AUTH_TT` |
| identity_authorized_bc_id {+Conditional} | string | Required when `identity_type` is `BC_AUTH_TT`. ⏎ ID of the Business Center that a TikTok Account User in Business Center identity is associated with. |
| rule_spec **(Required)** | object | Rule of the audience. |
| ↳ inclusion_rule_set **(Required)** | object | Details of the inclusion rule set. |
| ↳↳ operator **(Required)** | string | Operator between the inclusion rules within the inclusion rule set. ⏎ Enum value: `OR`. ⏎ If you provide more than one inclusion rule, the inclusion rules will be combined using OR logic to broaden the audience. |
| ↳↳ rules **(Required)** | object[] | A list of inclusion rules within the inclusion rule set. |
| ↳↳↳ event_source_ids | string[] | Required when `audience_type` is not `ENGAGEMENT` or `LEAD_GENERATION`. ⏎ List of event source IDs of the rule. ⏎ •  For an Engagement Audience, use ad group IDs as event source IDs. If not specified, all available event source IDs will be used. • For an Organic Engagement Audience, use TikTok post IDs as event source IDs. You can use [/identity/video/get/](doc:1740218475032577) to get TikTok post IDs. The maximum allowed number of TikTok post IDs is 10.  • For a Live Engagement Audience, use live video ID as event source IDs. You can use [/identity/live/get/](doc:1785238052792321) to get live video IDs. The maximum allowed number of live video IDs is 10.  • For an App Activity Audience, use App IDs as event source IDs.  • For a Website Traffic Audience, use pixel IDs as event source IDs.  • For a Lead Generation Audience, do not pass in this field. Otherwise, an error will occur. If not specified, all available event source IDs will be used. • For a Business Account Audience, use core user IDs of the advertisers. You can use [/user/info/](doc:1739665513181185) to get a core user ID.  • For a Shop Activity Audience, use TikTok Shop IDs as event source IDs. You can use [/store/list/](doc:1752267762718722) to get TikTok Shop IDs. • For an Offline Activity Audience, use Offline Event set IDs as event source IDs. You can use [/offline/get/](doc:1765596808589313) to get Offline Event set IDs. |
| ↳↳↳ retention_days **(Required)** | number | Audience lookback window. ⏎ For enum values, see [Enumerations - Lookback window](doc:1737174886619138). ⏎ **Note**:  • If `audience_type` = `BUSINESS_ACCOUNT`, and the `value` in the `filters` object is not `BUSINESS ACCOUNT PROFILE FOLLOW`, then `retention_days` must be `7`, `14`, or `30`. • If `audience_type` = `ENGAGEMENT_LIVE_VIDEO` or `ENGAGEMENT_ORGANIC_VIDEO`, then `retention_days` must be `7`, `14`, or `30`. • To avoid confusion between `retention_days` and `retention_in_days`, we'll rename `retention_days` in the next API version. |
| ↳↳↳ filter_set **(Required)** | object | The set of filters for each inclusion rule. |
| ↳↳↳↳ operator **(Required)** | string | Operator between filters in the `filters` object array. ⏎ Enum value: `OR`. ⏎ Within each inclusion rule, you can only specify one object in `filters`. |
| ↳↳↳↳ filters **(Required)** | object[] | An array of filters on previous audience actions and optionally also on URL keywords or parameters. ⏎ Max size: 1. |
| ↳↳↳↳↳ field **(Required)** | string | Filter field. ⏎ Enum value:  • `EVENT`: To include the people who've carried out a certain action in the past few days as indicated by `retention_days`. |
| ↳↳↳↳↳ operator **(Required)** | string | Filter operator between filter field and filter value. ⏎ Enum value:  • `EQ`: equals. |
| ↳↳↳↳↳ value **(Required)** | string | Filter value. ⏎ For enum values, see [Enumeration - Filter Value](doc:1737174886619138). |
| ↳↳↳↳↳ parameter_filters | object[] | List of filters on URL keywords or parameters. ⏎ Within `parameter_filters`, you can add a maximum of one URL keyword filter (with `field` set to `URL`) and 10 parameter filters (with `field` not set to `URL`) . ⏎ If specified, these filters (`parameter_filters`) are combined with the action filter (as specified by `field`, `operator` and `value`) using default AND logic to form the inclusion rule. ⏎ For example, if `retention_days` is `30` and `filter_set` is set to `{"operator": "OR", "filters":[{"field":"EVENT","operator":"EQ", "value":"PIXEL COMPLETE PAYMENT"},"parameter_filters":[{"field":"URL","operator":"CONTAINS","value":"us"}]]}`, the inclusion rule will create an audience that includes people who carried out the "Complete Payment" action on a webpage with "us" included in the page URL within the past 30 days on the website where the Pixel is installed. |
| ↳↳↳↳↳↳ field {+Conditional} | string | Required when `parameter_filters` within `inclusion_rule_set` is passed. ⏎ Filter condition. ⏎ Use this field to specify whether to filter URL keywords, or [Web Event parameters reported via the Pixel](doc:1739585702922241). ⏎ Enum value:  • `URL`: URL keywords.  • `CONTENT_TYPE`: the parameter `content_type`. • `PRICE`: the parameter `price`.  •  `VALUE`: the parameter `value`. • `CONTENT_ID`: the parameter `content_id`. • `CONTENT_CATEGORY`: the parameter `content_category`. |

| ↳↳↳↳↳↳ values {+Conditional} | string[] | Required when `parameter_filters` within `inclusion_rule_set` is passed. ⏎ A list of filter values. ⏎ Max size: 10. ⏎ Length limit for each value: 100 characters. ⏎ If you specify multiple values, the values will be combined using OR logic. |

### Example

``` xcodeblock
(code curl http)
curl --location --request POST 'https://business-api.tiktok.com/open_api/v1.3/dmp/custom_audience/rule/create/' \
--header 'Content-Type: application/json' \
--header 'Access-Token: {{Access-Token}}' \
--data '{
    "advertiser_id": "{{advertiser_id}}",
    "custom_audience_name": "{{custom_audience_name}}",
    "audience_type": "OFFLINE",
    "rule_spec": {
        "inclusion_rule_set": {
            "operator": "OR",
            "rules": [
                {
                    "event_source_ids": [
                        "{{event_source_id}}"
                    ],
                    "retention_days": 7,
                    "filter_set": {
                        "operator": "OR",
                        "filters": [
                            {
                                "field": "EVENT",
                                "operator": "EQ",
                                "value": "OFFLINE COMPLETE PAYMENT"
                            }
                        ]
                    }
                }
            ]
        }
    }
}'
(/code)
```
