# Register MCP servers
> Đường dẫn: Skill and MCP management > Get started with MCP server management > Register MCP servers
This article covers the complete flow from registering a new MCP server to making it live on Agentic Hub.

## Navigate to My Agentic Hub
All MCP server management tasks begin from the **My Agentic Hub** page. To access it:

1. Navigate to the [TikTok for Business Developers portal](https://business-api.tiktok.com/portal) and click **Log in** in the top-right corner.

![click Log in in the top-right corner](https://images.ctfassets.net/5jqet0ab9qci/2EjQ1uz4t9uaoueIej0FLb/3f7fc70471c35aba30f68f36b5520a35/WnUib8PjXo4BlxxIMbdmpPZOyNd.png)

2. Click **My Agentic Hub** in the top-right navigation to open the MCP server management page.

![Click My Agentic Hub in the top-right navigation](https://images.ctfassets.net/5jqet0ab9qci/5dr7cAwmjRCTPnypjpyoxL/a24a2563461a600a0e11dca2e06916e4/DhshbO9vKoS1eoxdf4dmpmBryKT.png)

> **Note:** 
> All procedures in this documentation assume you are logged in and viewing the My Agentic Hub page. These navigation steps are not repeated in subsequent sections.

## Register a new MCP server
Register your MCP server to centralize management, streamline reviews, and distribute your solutions to advertisers through TikTok for Business Agentic Hub.

**Steps**

1. On the My Agentic Hub page, click **Upload New** in the top-left corner and select **Register MCP server**.

![Company info](https://images.ctfassets.net/5jqet0ab9qci/1ZJUL3XMSH8NEmO96Am2dM/4655b9255e33d08cf97e1d4d219088e3/Pt6WbNbHqoUMUhxu9M2m5H9fykc.png)

![select Register MCP server](https://images.ctfassets.net/5jqet0ab9qci/31pEH3u6uOFkEMAnryvpBD/a1c2041e38ce4037c5fe29b120e3280c/LMuxbEtproev1AxUG6EmdgQvyPo.png)

2. Complete the upload form with the following required fields:

> **Important:** 
> Choose your Server name carefully. Once submitted, this field cannot be modified. If you need to change the name later, you must delete the MCP server and register a new one.

**Secondary technical contact email**The email address for the backup contact. The email must differ from the primary contact email.
**Server identity & listing copy****Server name**The display name of your MCP server on the Agentic Hub. Ensure the name is brand-focused and avoid redundant terms like "MCP" or "Server".
**Version (SemVer)**The initial semantic version of this MCP server in X.Y.Z format (e.g., 1.0.0). This is used for rigorous version tracking.
**Server logo**The official logo image for the MCP server. Recommended aspect ratio: 1:1 (square). File format: SVG format is preferred and PNG is accepted (max 10 MB).
**Screenshots**The screenshots that showcase the value your MCP server provides (such as architecture diagrams, data flow charts, or marketing materials). Up to 3 images are allowed. Supported file formats: .PNG/.JPG/.WebP. Max file size for each image: 10 MB.
**Tagline**A punchy, one-line value proposition that instantly tells users what your server does. Length limit: 55 characters. This information will appear on the Agentic Hub listing as the card subtitle.
**Short description**A brief summary highlighting core use cases and benefits. Length limit: 100 words. Required length: 50-100 words. This information will appear on the Agentic Hub listing in the card body and the detail page.
**Long description**A comprehensive breakdown of your server's capabilities, supported tools, and prerequisites. No length limit. This information will appear on the Agentic Hub listing in the detail page.
**Category**The functional category that best describes your MCP server.
**Industries**The industry verticals that your MCP server is designed to serve.
**Countries / availability**The markets where you want to offer this MCP server. The Agentic Hub listing will be hidden from users outside these specific regions.
**Documentation URL**A live URL linking directly to the official technical documentation for your MCP server.
**Requires paid subscription?**A clarification of whether users need an active paid plan, license key, or specific account tier on your platform in order to successfully use this MCP server.
**Endpoint & transport****Remote MCP server URL**The live, publicly accessible URL where your server is hosted. Provide only one URL per submission.
**Transport: Streamable HTTP is supported — the server URL is verified as a Streamable HTTP endpoint at pre-check.**A confirmation that your infrastructure implements proper HTTP streaming protocols required by the MCP specification.
**Our infrastructure accepts inbound requests from TikTok's published gateway egress IP ranges.**A confirmation that you agree to configure your WAF (Web Application Firewall) or security groups to allow inbound traffic from TikTok's official IP allowlist in the future (that is, you won't block our platform via firewalls).
**Capability declaration****Tools — at least 1 required**A completed CSV file defining the tool signatures, titles, descriptions, and safety annotations . Download the official [Tools Configuration Template](https://bytedance.my.larkoffice.com/sheets/AIgpsEGB8hPxbmt1tO0mWtC4yHh). The file should map out every tool your server offers. Our pre-check diffs the capabilities declared in this CSV file against your server.
**Read/Write capability**A high-level access categorization that matches the tool annotations in your tools CSV file. • If the safety_annotation of all your tools is readOnlyHint, select **Read only**. • If the safety_annotation of all your tools is destructiveHint or writeHint, select **Write only**. • If the safety_annotation of your tools are a mixture of readOnlyHint and destructiveHint or writeHint, select **Read + write**.
**All tools have user-friendly titles and semantic annotations.**A confirmation that your tool names and descriptions are optimized for LLM comprehension. Good semantic annotations act as system prompts, allowing the AI to accurately understand when and how to reason about your tools.
**Safety annotations are accurately applied to every tool — readOnlyHint or destructiveHint / writeHint on each, not only mutative ones.**A confirmation that you have correctly flagged the mutative and non-mutative action for each tool.
**Tool specifications conform to MCP guidelines.**A confirmation that your tool specifications strictly follow [the official MCP guidelines](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).
**Authentication****Authentication type**The authentication method for your MCP server (that is, either requiring standard OAuth to access user-specific data, or requiring no authentication).
**Dynamic Client Registration (DCR / CIMD)**(Required if using OAuth) A confirmation that your MCP server supports Dynamic Client Registration. This allows the agent to programmatically register and obtain unique OAuth client IDs/secrets, saving the user from manual setup in a developer portal.
**Authorization URL**(Required if using OAuth) The authorization URL where users are redirected to grant permissions. Example: https://auth.partner.com/oauth/authorize This must resolve to your verified company domain to prevent phishing.
**TikTok's redirect URI (shown in-form) is allowlisted on our OAuth provider: ****https://business.tiktok.com/agentic/oauth****/callback**(Required if using OAuth) A confirmation that you have added TikTok's specific callback URL to your authorized redirect URIs in your identity provider settings, ensuring the OAuth handshake will succeed.
**Data handling & disclosure****Data handling attestations**A confirmation of your data lifecycle practices. Select all statements that apply: • The server only accesses data explicitly requested by the user. • No data is stored beyond session requirem • All transmission is encrypted (HTTPS/TLS) • GDPR compliant where applicable.
**Third-party access**A declaration of any third-party access dependencies required by your MCP server.
**Review access****Test account credentials**The dedicated testing credentials provided securely for our review team to verify your submission. **Credentials must cover the full OAuth flow and every declared tool. Otherwise, the review will be blocked.**
**Test account setup instructions**A step-by-step guide explaining how reviewers should log in, trigger specific features, and navigate any staging environment nuances.
**The test account includes representative sample data.**A confirmation that the test account is pre-populated with mock data (like campaigns, analytics, or dummy assets) so reviewers can test read/write flows successfully.
**All declared tools can be exercised with that data.**A confirmation that no permission errors or gated features will prevent the review team from rigorously testing every tool listed in your CSV.
**Launch readiness & legal****GA date**The date when your MCP server became generally available, in YYYY-MM-DD format.
**Privacy policy URL**The live link to the privacy policy document for your MCP server.
**Terms of service URL**The live link to the terms of service document for your MCP server.
**Support channel**The URL or email address directing users to your helpdesk, community forum, or dedicated support team.

## Understand the review process
After submission, your MCP server enters the review pipeline. The TikTok team evaluates your MCP server for quality, compliance with marketplace policies, and functional completeness. 

During this time, the review team will:
- Verify that your server URL is reachable.
- Perform a dry-run of your OAuth setup to ensure users can authorize successfully.
- Validate your CSV file to confirm all tools are properly annotated.
- Use your test account to verify that the tools function correctly with your sample data.
Monitor progress from the **My Agentic Hub** page by checking the **Status** column:

| Status | Meaning |
|---|---|
| Pending Review | Your MCP server is in the review queue and awaiting evaluation by the TikTok team. |
| Published | Your MCP server has passed review and has been published. |
| Rejected | The review identified issues that must be resolved. View feedback and resubmit. See [Resubmit a rejected MCP server](https://business-api.tiktok.com/portal/docs/troubleshoot-mcp-server-issues/v1.3#anchor-0-1). |
