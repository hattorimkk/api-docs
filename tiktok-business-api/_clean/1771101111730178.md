# Setup guide for App
> Đường dẫn: Marketing API > Ad Measurement > Guides > Events API 2.0 > Events API for App > Setup guide for App
> **Note:** 
> Reporting App Events using Events API 2.0 is currently an allowlist-only feature. If you would like to access it, please contact your TikTok representative.

This guide walks you through the process of setting up Events API 2.0 for App.

# Create an app and generate your TikTok App ID
A user in an Admin or Operator role needs to perform these steps in your Ads Manager account.

## Access Events Manager
To get started with app creation, navigate to **Tools ➤ Events** in your TikTok Ads Manager account.

## Create your app

- If you do not already have a data connection set up, select **"Get started"**.
- If you already have other data connections set up, select **"Connect data source"**.

Select **"App"** and proceed.

## Provide your app details

Fill in your app download URL and proceed. The app icon, app name, and app ID will be populated automatically.

Select **"Use TikTok Events API"** and proceed.

The app is now created, and you will see some recommended events for your app. Recommendations are provided for specific verticals. Once you have noted these down, click **Finish** to be taken to your app detail page.

## Generate your TikTok App ID

Note down your **App ID**, and copy your **TikTok App ID**. Both are required for integration.

Your **App ID** will be in either reverse DNS format (Android), or short numerical string (iOS) typically present in app store or play store URLs. Your **TikTok App ID** is a longer numerical string, and specific to your ad account. This will be used as the `event_source_id` for sending app events via Events API 2.0.

## Generate your access token
To authenticate Events API calls, you need an access token. You can generate one in the "**Settings**" tab. To learn more about how to generate an access token, refer to [Events API 2.0 - Authentication](doc:1771101130925058).

# Report an App Event
To report an event  (such as `LaunchAPP` or `Purchase`) from a mobile app (Android or iOS) to TikTok, call the Events API 2.0 endpoint [/event/track/](doc:1771101303285761).

**Endpoint** https://business-api.tiktok.com/open_api/v1.3/event/track/

**Method** POST

**Header**

| Field | Data Type | Description |
|---|---|---|
| Access-Token  **(Required)** | string | Authorized access token. ⏎ To obtain an access token, refer to [Events API 2.0 - Authentication](doc:1771101130925058). |
| Content-Type  **(Required)** | string | Request message type. ⏎ Allowed format: `application/json`. |

#### `user` parameters

| Field | Data Type | Description |
|---|---|---|
| email | string ⏎ or string[] | **SHA-256 hashing is required.** ⏎ The email address, or email addresses of the customer. ⏎ Follow the instructions below to obtain a valid value:  • **Trim** any leading and trailing spaces of each email before hashing.  • **Lowercase** all characters before hashing. • **Hash** the normalized email values using SHA-256.**Example**:  •  Original: " ALICE_abc@gmail.com "  •  Normalized: "alice_abc@gmail.com" (leading and trailing spaces trimmed and lowercased)  •  SHA-256 hashed: "848a771458438fc2ec420560d769fb9b9b86851ee338ec56517baabd79d3bb4f" |
| phone | string ⏎ or string[] | **SHA-256 hashing is required. ** ⏎ The phone number or phone numbers of the customer. ⏎ Follow the instructions below to obtain a valid value:  • **Normalize** the phone number to [E.164 format](https://www.twilio.com/docs/glossary/what-e164) (for example, "+12133734253"). We recommend using [https://github.com/catamphetamine/libphonenumber-js](https://github.com/catamphetamine/libphonenumber-js) for E.164 parsing.  • **Country code** must be included and prefixed with the `+` sign, without any parentheses or leading `0`s. For example, a US phone number should be prefixed with the `+1` country code. •  **No spaces, letters or symbols** except the `+` for the country code are included.  • **SHA-256 hash** the phone number after normalizing. **Example**:  •  Original: "(+1)2133734253" •  Normalized to E.164 format: "+12133734253" •  SHA256 hashed: "9f7ec22d72092cd3c0b58726ed9c2d91b92e51a3f29837508fb2948bb22dd2fd" |
| idfa | string | The iOS IDFA. ⏎ For iOS 14 and above, ensure that IDFA data collection follows [Apple’s policies](https://developer.apple.com/app-store/user-privacy-and-data-use/). Both raw and SHA-256 IDFAs are accepted: • For raw IDFAs, all characters must be **UPPERCASE**.  • For SHA-256 IDFAs, all characters must be **lowercase**, and any **leading/trailing spaces** must be **trimmed** before hashing. |
| idfv | string | The iOS IDFV. |
| gaid | string | The GAID (Google Advertising ID). ⏎ Both raw and SHA-256 GAIDs are accepted. ⏎ For both raw and SHA-256 GAIDs: • All characters must be **lowercase**. • **Leading/trailing spaces** must be **trimmed** before hashing |
| ip | string | Non-hashed ** public IP** address of the user's device. ⏎ To increase the probability of matching website visitor events with TikTok ads, we recommend sending both `ip` and `user_agent`. |
| user_agent | string | Non-hashed user agent from the user’s device. ⏎ To increase the probability of matching website visitor events with TikTok ads, we recommend sending both `ip` and `user_agent`. |
| locale | string | The BCP 47 language identifier. ⏎ For reference, refer to [the IETF BCP 47 standardized code](https://www.rfc-editor.org/rfc/bcp/bcp47.txt). |
| att_status | string | Whether the user has authorized your mobile app to access app-related data for measuring the user or the device. This is an iOS only field. ⏎ Enum values:  • `AUTHORIZED`: The user has authorized access to app-related data that can be used for measuring the user or the device.  •  `DENIED`: The user has not agreed to authorize your mobile app to access app-related data for measuring the user or the device via [Apple's AppTrackingTransparency framework](https://developer.apple.com/documentation/apptrackingtransparency). ⏎ If this field is set to `DENIED`, TikTok will not use the PII data (for instance, user email address or phone number) in this App Event for user-level matching. • `NOT_DETERMINED`: The user has not yet received an authorization request to authorize access to app-related data that can be used for measuring the user or the device. • `RESTRICTED`: The authorization to access app-related data is restricted. •  `NOT_APPLICABLE`: The iOS version is below 14 or the device is running Android. |

#### `ad` parameters

| Field | Data Type | Description |
|---|---|---|
| callback | string | Callback information to help attribute events |
| campaign_id | string | The TikTok campaign ID associated with the touchpoint, typically parsed from the landing URL or deeplink. |
| ad_id | string | The TikTok ad group ID associated with the touchpoint, typically parsed from the landing URL or deeplink. |
| creative_id | string | The TikTok ad ID associated with the touchpoint, typically parsed from the landing URL or deeplink. |
| is_retargeting | boolean | Whether the user is a retargeting user. |
| attributed | boolean | Whether the event is attributed. |
| attribution_type | string | Attribution type. |
| attribution_provider | string | Attribution provider. |
| attribution_share | float | Attribution share score. ⏎ A score provided by you per conversion, representing the portion of credit TikTok should receive for the conversion. A greater value indicates a larger credit share for TikTok. ⏎ Examples: • 0.0: No credit. • 0.5: Partial credit. • 1.0: Full credit. |
| attribution_value | float | The portion of the conversion's ROAS that your attribution system assigns to this TikTok touchpoint. ⏎ Typical usage: multiply the conversion value by the touchpoint's credit share (`attribution_share`) and pass the result here. ⏎ Example: an order worth $120 credited 25% to a TikTok touchpoint under a linear model yields `attribution_value = 30.0` for that event. |
| attribution_model | string | The attribution model that is used to attribute the event. ⏎ Examples: • `even_weight`: alias for evenly distributed credit. • `first_click`: full credit to the first click in the journey. • `first_touch`: full credit to the first touchpoint in the journey. • `last_click`: full credit to the last click in the journey. • `last_touch`: full credit to the last touchpoint in the journey. • `linear`: equal credit across every attributed touchpoint. |
| touchpoint_type | string | The type of TikTok touchpoint that received credit for this event. ⏎ Examples: • `click`: the user clicked a TikTok ad or a link that originated from a TikTok ad. • `view`: the user was served a TikTok ad impression without clicking. • `engaged_view`: the user watched a video ad for a qualifying duration (for example, 6 seconds or more) without clicking. • `engaged_click`: the user clicked and interacted with a rich media ad format (such as a Playable Ad). • `click_to_store`: the user clicked an ad that directed them straight to an app marketplace (for example, Apple App Store or Google Play). • `hybrid`: a mix of click and view signals contributed to the touchpoint. • `other`: any touchpoint that does not fit the categories above. |
| touchpoint_ts | integer | The time the TikTok touchpoint occurred, expressed as a Unix timestamp in seconds in the UTC+0 time zone. |
| touchpoint_url | string | The URL where the touchpoint was captured. ⏎ An example is the landing page URL that a user reached after clicking a TikTok ad. |
| attribution_window_hr_click | integer | The click-through attribution window, expressed in **hours**. ⏎ It defines the maximum interval between a TikTok click touchpoint and the conversion for which the click is still eligible to receive credit. ⏎ Examples: `1`, `24` (1 day), `168` (7 days), `720` (30 days). |
| attribution_window_hr_view | integer | The view-through attribution window, expressed in **hours**. ⏎ It defines the maximum interval between a TikTok view touchpoint (impression) and the conversion for which the view is still eligible to receive credit. ⏎ Examples: `1`, `24` (1 day), `168` (7 days) |
| attribution_method | string | The technical method used to associate the touchpoint with the conversion. ⏎ Examples: • `pixel`: matched through the TikTok pixel on the advertiser's website. • `PPS`: matched through Post-Purchase Survey. • `deeplink`: matched through a deeplink click identifier. • `modeled`: attribution produced by a statistical or ML model rather than a deterministic match. • `SKAN`: matched through Apple's SKAdNetwork framework. • `shop`: matched through a TikTok Shop signal. |
| decline_reason | string | The reason your system declined to assign attribution credit to TikTok for this event. ⏎ Examples: • `attributed_to_other_source`: another channel received the credit. • `organic`: no paid channel received credit; treated as an organic conversion. • `outside_attribution_window`: the TikTok touchpoint fell outside the click or view window. • `invalid_event`: the event failed a partner-side validation check. • `fraud_detected`: the touchpoint was flagged as fraudulent. • `duplicate_event`: the conversion was already counted in a prior report. • `low_confidence_match`: the touchpoint-to-conversion match did not meet the confidence threshold. • `missing_touchpoint`: no eligible TikTok touchpoint was found. • `missing_click_id`: the required TikTok click identifier was absent. • `privacy_threshold_filtered`: the event was filtered out by a privacy threshold. • `unsupported_signal`: the signal type is not supported by the attribution engine. • `other`: any other reason that does not fit the categories above. |
| utm_id | string | The unique identifier of the marketing campaign or UTM parameter set that produced the touchpoint. ⏎ It corresponds to the `utm_id` parameter in the landing URL. ⏎ Use this field to report the custom campaign identifier from your landing page URL. This is particularly useful if your internal tracking relies on custom UTM values rather than TikTok's default campaign IDs. ⏎ Example: `summer2026_launch`. |
| utm_source | string | The traffic source that referred the user to the landing page, as captured in the `utm_source` URL parameter. ⏎ It typically identifies the platform or property that hosted the ad. ⏎ Example: `tiktok`. |
| utm_medium | string | The marketing medium that delivered the traffic, as captured in the `utm_medium` URL parameter. ⏎ It identifies the category of the placement rather than the platform. ⏎ Examples: `cpc`, `paid_social`, `display`. |
| utm_campaign | string | The campaign name that produced the touchpoint, as captured in the `utm_campaign` URL parameter. ⏎ It is used to attribute performance to a specific marketing initiative within the traffic source. ⏎ Example: `summer2026_launch_us`. |

## Sample payload
The following is an example of a request for reporting a single `Purchase` App Event.
```http
// curl
curl --location --request POST 'https://business-api.tiktok.com/open_api/v1.3/event/track/' \
--header 'Access-Token: {{ACCESS_TOKEN}}' \
--header 'Content-Type: application/json' \
--data-raw '{
  "event_source": "app",
  "event_source_id": "{{TIKTOK_APP_ID}}",
  "data": [
    {
      "event": "InstallApp",
      "event_time": 1687758765,
      "user": {
        "phone": "{{HASHED_PHONE}}",
        "email": "{{HASHED_EMAIL}}",
        "idfa": "{{IDFA}}",
        "idfv": "{{IDFV}}",
        "gaid": "{{GAID}}",
        "att_status": "AUTHORIZED",
        "locale": "en-US"
      },
      "app": {
        "app_id": "com.test.flyingsneakers",
        "app_name": "Flying Sneakers",
        "app_version": "3.0.2"
      },
      "ad": {
        "attributed": true,
        "callback": "{{CALLBACK}}",
        "campaign_id": "1700817380525057",
        "ad_id": "1700817380806706",
        "creative_id": "1700817378256945",
        "is_retargeting": false,        
        "attribution_type": "click_through"
      },
      "properties": {
        "currency": "USD",
        "value": 200.0,
        "content_type": "product",
        "contents": [
          {
            "price": 100.0,
            "quantity": 2,
            "content_id": "12345",
            "content_name": "Fancy-AirMax2.0 Black",
            "content_category": "Shoes - Running Shoes",
            "brand": "Fancy Sneakers"
          }
        ]
      }
    }
  ]
}'
```
