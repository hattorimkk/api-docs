# Optimize tool usage in a custom agent
> Đường dẫn: TikTok for Business MCP Server > How to connect a custom agent to TikTok for Business MCP Server > Optimize tool usage in a custom agent
When [building custom agents](slug:how-to-connect-a-custom-agent-to-tiktok-for-business-mcp-server) that integrate with numerous TikTok for Business MCP tools, token consumption can quickly escalate. The primary driver of this cost is preloading all tool definitions—especially those with verbose natural language descriptions—into the agent's context. This guide outlines best practices for optimizing tool usage.

## Identify token consumption sources
Token usage in MCP integrations typically comes from the following areas:
- **Tool definitions:** Loading large numbers of input schemas and descriptions before the agent knows which tools it needs.
- **Tool results:** Passing large, unfiltered JSON responses back to the model.
- **Agent history:** Retaining tool calls, results, and messages across a long session.
- **Agent reasoning:** Repeating tool selection and execution when the available tools are difficult to distinguish.
For example, if an agent loads 40 tools but typically uses only two, the other 38 definitions occupy context without helping the current task. Similar or overlapping definitions can also make tool and parameter selection less reliable.

## Implement tool search and dynamic tool loading
Instead of preloading all tools, use a retrieval system to load tool schemas dynamically based on the user's prompt.
1. **Tool registry:** Maintain a centralized directory of all available tools and their metadata.
2. **Hybrid search:** Use a combination of keyword search (such as [BM25](https://en.wikipedia.org/wiki/Okapi_BM25)) for exact API name matches and vector search (such as [embeddings](https://developers.openai.com/api/docs/guides/embeddings)) for semantic understanding to retrieve the most relevant tools.
3. **Dynamic loading:** Load only the schemas of the top-ranked tools into the agent's context, and load additional tools only when the task requires them.

## Compress tool results
After narrowing the available tools, reduce the size of their outputs before returning them to the agent. Filter unused fields, aggregate records when the task needs a summary, and paginate long result sets. If an API returns dozens of fields but the next decision depends on only three, retain those three instead of passing the full response through every subsequent turn.

## Implement context pruning and compaction
Long-running tasks can still accumulate messages, tool calls, and results after tool loading and result compression are in place. Replace completed or redundant history with a structured task state that records completed steps, key findings, unresolved issues, and pending actions. Keep the original details only when they are still needed for the next decision or for verification.
