# Request user authorization
> Đường dẫn: API Reference > MCP Authorization > Request user authorization
Use this endpoint to open a browser-based authorization page where the user signs in to TikTok for Business and approves your request.

After the user grants approval, the server redirects the browser to your registered `redirect_uri` with an authorization code.

> **Note:** 
> •  For security reasons, the user might be required to complete email verification to authorize the request. If you need to bypass this verification step for a trusted client and `redirect_uri`, contact your TikTok representative.
>
> •  Do not hardcode the authorization URL. Always dynamically retrieve it from the `authorization_endpoint` field in [/open_mcp/{server}/oauth/.well-known/openid-configuration/](slug:get-authorization-server-metadata).

# Request
**Endpoint** https://business-api.tiktok.com/portal/mcp-tt4b-authorize/

**Method** GET

**Query parameters**

| Field | Data Type | Description |
|---|---|---|
| response_type  **(Required)** | string | The requested response type. ⏎ Enum value: • `code`: You will receive an authorization code to exchange for a token. |
| resource  **(Required)** | string | The specific TikTok for Business MCP server URL. ⏎ Enum values: • `https://business-api.tiktok.com/open_mcp/tt-ads-mcp-flat` • `https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer` ⏎ To learn more about how these server URLs differ, see [Choose your server URL](https://business-api.tiktok.com/portal/docs/how-to-connect-a-custom-agent-to-tiktok-for-business-mcp-server/v1.3#anchor-3). |
| client_id  **(Required)** | string | The registered client ID. ⏎ Ensure this ID exists and is valid. ⏎ To obtain the client ID, use [/open_mcp/{server}/oauth/register/](slug:register-a-client-application). |
| redirect_uri  **(Required)** | string | The redirect URI for this specific authorization request. ⏎ Ensure it exactly matches one of the redirect URIs you registered for the client application. |
| scope  **(Required)** | string | The requested permission scope. ⏎ Enum value: • `mcp:tt4b`: the necessary permissions to access TikTok for Business MCP server features. |
| state | string | A random string generated by your client application. ⏎ The server will echo this exact value back to your `redirect_uri` upon redirection. You need to verify that the returned value matches the one you originally sent. ⏎ You are highly recommended to include this to prevent Cross-Site Request Forgery (CSRF) attacks and for request tracking. |
| code_challenge  **(Required)** | string | The PKCE (Proof Key for Code Exchange) code challenge string, a hashed version of a random secret string (the `code_verifier`) generated by your client application. ⏎ This is part of the PKCE (Proof Key for Code Exchange) security flow, which prevents hackers from intercepting your authorization code by creating a dynamic, one-time secret for every login. ⏎ To create the string, follow these steps: • Generate a `code_verifier` (a random, secure string between 43 and 128 characters).  • Create the `code_challenge` by hashing your `code_verifier` using SHA-256 and Base64-URL encoding the result. • Send this challenge now. Later, when exchanging your authorization code for an access token, you will send the original `code_verifier`. The server will compare them to prove that the application exchanging the code is the exact same app that requested it. |
| code_challenge_method  **(Required)** | string | The hashing algorithm used to create your `code_challenge` from your `code_verifier`. ⏎ Enum value: • `S256`: To securely hash your `code_verifier` using the SHA-256 algorithm before sending it. |

## Example
> **Note:** 
> The example below uses `https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer` as the `{{resource}}` value. You can replace this with your chosen server value.

```http
// curl
https://business-api.tiktok.com/portal/mcp-tt4b-authorize?response_type=code&resource=https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer&client_id={{client_id}}&redirect_uri={{redirect_uri}}&scope=mcp:tt4b&code_challenge={{code_challenge}}&code_challenge_method=S256
```

# Response

On approval, the authorization server redirects the browser to the specified `redirect_uri` with the following query parameters.

| Field | Data Type | Description |
|---|---|---|
| code | string | The authorization code granted to you after user approval. |
| state | string | Returned only when `state` is included in the request. ⏎ The state value echoed back from your initial request. |

## Example
```http
// curl
https://example.com/oauth/callback?code={{code}}&state={{state}}
```

## Error response
Authorization failures are rendered on the authorization page in the user's browser rather than returned as JSON.
