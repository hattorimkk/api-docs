# Send Custom Attribution data to TikTok via Events API 2.0
> Đường dẫn: Marketing API > Ad Measurement > Guides > Events API 2.0 > Send Custom Attribution data to TikTok via Events API 2.0
## Why send Custom Attribution data to TikTok
Advertisers may evaluate TikTok performance using attribution methodologies defined outside of TikTok — for example, within an internal Business Intelligence (BI) system or through a third-party attribution provider. These methodologies may use different attribution models, lookback windows, touchpoints, or crediting rules than TikTok's own attribution. Without visibility into these attribution decisions, TikTok may evaluate and optimize ad performance differently from the way your business measures success.

**Custom Attribution** data gives TikTok visibility into attribution outcomes your business has already determined. Rather than asking TikTok to re-create your attribution methodology, you send the resulting attribution information — including which TikTok touchpoints received credit and how that credit was assigned. Providing this data creates the signal foundation for TikTok to better understand and align with the attribution methodology that your business uses to evaluate advertising performance. As Custom Attribution capabilities develop, this data may support use cases across areas such as measurement, diagnostics, ad delivery, optimization, testing, and related tooling.

## Availability
Custom Attribution is designed to enhance your campaign performance. While specific optimization outcomes and downstream applications will continuously expand, our goal is to leverage your data to drive maximum impact as capabilities roll out.

## Custom Attribution data vs. first-party event data
First-party event data tells TikTok what happened on your website or app — for example, a purchase, registration, or add-to-cart. Custom Attribution data tells TikTok how your attribution system assigned credit for that outcome, based on the attribution methodology your business uses. The two are complementary.

## When to use the Events API path
Choose the [Events API](slug:report-app-web-offline-or-crm-events) integration path when:
- Your source of truth for attribution lives in an **internal system** or a data warehouse that you control.
- You already have an active integration with TikTok's Events API 2.0 for first-party conversion events, or you are prepared to build one.
- You require end-to-end control over the payload structure, the attribution model, and the data delivery cadence.

## What you send
Structurally, a Custom Attribution signal is an event you POST to the TikTok Events API 2.0 endpoint. It functions exactly like a standard conversion event, but with three critical distinctions:
- The event name is a **custom event** prefixed with `sot_` (for example, `sot_purchase`).
- The `ad` object contains the attribution metadata generated by your internal system, including `attribution_share`, `attribution_model`, `touchpoint_type`, `touchpoint_ts`, and related fields.
- You transmit **one event per attributed TikTok touchpoint**, rather than one event per conversion.
### Rule 1: Report each attributed touchpoint as an independent Custom Attribution event
Every attributed TikTok touchpoint must be reported as a standalone Custom Attribution event. If your attribution model distributes credit across multiple TikTok touchpoints for a single conversion, you must send one event per touchpoint instead of a single aggregated event.
- **One event per attributed touchpoint**: If a conversion is credited to three TikTok touchpoints under a linear model, you must send three Custom Attribution events. Each event describes exactly one touchpoint and carries its specific share of credit in `ad.attribution_share`.
- **One event per touchpoint, per model**: Within a single attribution model, a specific touchpoint is reported exactly once. Do not resend the same touchpoint under the same model for the same conversion.
- **Independent streams per model**: If you evaluate a single conversion under multiple attribution models (for example, linear and last-click), report each model as a separate stream of events. TikTok processes each model as its own distinct reporting channel.
### Rule 2: Name every Custom Attribution event with the `sot_` prefix and send it as a custom event
All Custom Attribution attribution events must adhere to the `sot_` naming convention and must be transmitted as custom events, not standard events. For instance, an attributed purchase must be reported as `sot_purchase`, not `purchase`.

### Rule 3: Use a distinct `event_id` for each Custom Attribution event
Assign each Custom Attribution event an `event_id` that is different from the `event_id` of the corresponding standard event.

**Recommended formats**
- Derive the Custom Attribution identifier from the original standard event identifier: `_sot_`.
- Or generate a new UUID (Universally Unique Identifier) for each Custom Attribution event.

## How to construct the payload
This section outlines the concrete steps for formatting a Custom Attribution event payload and transmitting it to [TikTok's Events API 2.0](slug:report-app-web-offline-or-crm-events).

### 1. Build one event per (conversion, touchpoint, attribution model) triple
For each conversion that your internal system attributes to TikTok, enumerate the attributed touchpoints under each attribution model you report. Send one event object for every (conversion, touchpoint, model) combination, populating the fields as follows:

**Event-level required fields**
- `event` : the Custom Attribution event name, prefixed with `sot_` (for example, `sot_purchase`, `sot_subscribe`, or `sot_lead`). Send as a custom event, not a standard event.
- `event_time`: the Unix timestamp in seconds (UTC+0) at which the **conversion** occurred. This is not the touchpoint time.
- `event_id`: a distinct identifier for this Custom Attribution event that remains stable across retries. Recommended format: `_sot_`, or a new UUID.

**Attribution metadata (the** **`ad`** **object)**

Include every attribution decision made by your internal system within the `ad` object. Populate the fields your system has data for; leave the rest empty rather than guessing.
- `ad.attribution_share`: the credit share assigned to this touchpoint, in `[0.0, 1.0]`.
- `ad.attribution_provider`: the name of your attribution system.
- `ad.attribution_model`: the attribution model applied (for example, `linear` or `last_click`).
- `ad.attribution_value`: the monetary value attributed to this TikTok touchpoint.
- `ad.campaign_id`, `ad.ad_id`, `ad.creative_id`: TikTok identifiers for the touchpoint, typically parsed from the landing URL or deeplink.
- `ad.touchpoint_type`: The type of TikTok touchpoint that received credit for this event.
- `ad.touchpoint_ts`: the Unix timestamp (seconds, UTC+0) at which the touchpoint occurred.
- `ad.touchpoint_url`: the URL captured at the touchpoint.
- `ad.attribution_window_hr_click` / `ad.attribution_window_hr_view`: the click and view windows applied, in hours.
- `ad.attribution_method`: the technical method used to associate the touchpoint with the conversion.
- `ad.decline_reason`: populate when `attribution_share = 0` to explain why credit was not assigned.
- `ad.utm_id`, `ad.utm_source`, `ad.utm_medium`, `ad.utm_campaign`: UTM parameters captured from the touchpoint URL.

**Order and revenue context (the** **`properties`** **object)**
- `properties.order_id` (**Required**): the transaction identifier. This must remain identical across all Custom Attribution events describing the same conversion.
- `properties.value` and `properties.currency`: the total conversion value and its currency.
- `properties.customer_type`: A categorical label indicating the customer segment associated with the conversion event (for example, `new` or `returning`).

**User identity and page or app context**
- Populate `user`, `page`, and `app` as needed by your standard setup.

Implementation notes on the example:
- `event_time`, `properties.order_id`, and `properties.value` are identical across all three objects as they reference the same conversion event.
- `event_id` differs across the three events; each carries the `_sot_` suffix.
- `ad.attribution_share` sums to `1.0` across the three events (0.33 + 0.33 + 0.34), and `ad.attribution_value` sums to the conversion value (`$40 + $40 + $40 = $120`).
- `ad.attribution_model` is `linear` on all three events. If the same order were also reported under a `last_click` model, that would be a separate stream of one or more events with `attribution_model = "last_click"` and its own `event_id` scheme.
