# Get Started
This guide walks you through the process of setting up Events API 2.0 for Web.

## Before you begin
- You should have access to TikTok Ads Manager that contains test event functionality and diagnostic tools that would help you during development testing and post integration validation.
- You must have created a pixel in the TikTok Ads Manager under **Tools** > **Events**.
- Once you create a pixel, you can send events via web site through [installing the pixel base code](doc:1739585702922241) or send events via Events API. The recommended best practice is to send both that would maximize your event coverage and campaign performance. Furthermore, with the dual channels setup, your campaign performance is protected against event disruption as the event signals will still come in from one channel when the other fails. If you are sending events from both Pixel SDK and Events API, you will need to set up [event deduplication](doc:1771100965992450).

If you don't already have a pixel, start with the first step to create a pixel. 
If you already have an existing pixel, skip the first step and start with the second step.

### 1. Create a Pixel
a. In [TikTok Ads Manager](https://ads.tiktok.com/i18n/home), navigate to  **Tools** > **Events** > **Connect data source** > **Web**.

b. Add your website.

c. Choose data connection method
- Option 1: **Partner integrations**
- Option 2: **Manual setup**

- If you select "**Partner Integrations**" , follow the on-screen steps to complete the setup process through one of the integration partners.
- If you choose "**Manual Setup**", you'll have the following setup options:
	- **TikTok Pixel** only
	- **Events API** only
	- **TikTok Pixel + Events** API

For optimal performance, we recommend setting up both TikTok Pixel and Events API. You'll need to name and create the Pixel, then follow the on-screen instructions to complete the setup and Pixel creation process.

### 2. Generate an access token
To authenticate Events API calls, you need an access token. To learn about how to obtain an access token, refer to [Events API 2.0 > Authentication](doc:1771101130925058).

Alternatively, you can **Generate access token** from pixel > **Settings**.

## Share Events with Events API
Events are actions a website visitor takes to achieve a business goal, like adding an item to a cart, filling out a form or making a purchase. Prior to integrating with the Events API, we recommend predefining which Events you are interested in sharing with TikTok to achieve your marketing objectives. You can add events and parameters to be sent with your payload.

For details of supported web events and parameters, see [Supported events - Web Standard Events](doc:1771101186666498).

## Share matching data within the events 
Events API for Web uses customer information such as TikTok Click IDs (`ttclid`), Advanced Matching, and additional signals like IP address and User Agent to match web visitor events with TikTok users. Once matched, information shared via the Events API can be used to build targeting audiences, inform the optimization algorithm and better measure campaign results.

# Verify Events setup
After creating the event, you can verify web data connection setup and monitor activity. If you are sending events from both Pixel SDK and Events API, you will need to set up [event deduplication](doc:1771100965992450).

For best practices of verifying Events API setup, see [Verify Events API setup](doc:1771100984456193).

# Best Practices for Optimal Performance

To achieve optimal performance with the Events API 2.0, we recommend the following settings:
1. Toggle on both first-party cookies and Automatic Advanced Matching from the Pixel settings in [TikTok Ads Manager](https://ads.tiktok.com/i18n/home) by navigating to **Tools** > **Events** > **Data sources**  > select a pixel > **Settings** tab. Refer to the screenshot below:

2. Set up [TikTok Click ID](doc:1771100879787009) and [cookies](doc:1771100936446977).
3. Send Advanced Matching Data. To learn more about Advanced Matching, refer to [About Advanced Matching for Web](https://ads.tiktok.com/help/article/advanced-matching-web?redirected=2).
As a best practice, we encourage you to send both email and phone numbers for all visitor events. Additionally, we recommend capturing visitors' emails and phone numbers early in the funnel for best results. This increases the probability of matching customers with people on TikTok. Finally, you can pass an External ID, such as a membership ID, along with the email and phone numbers for the best matching results. To learn more about External ID, refer to [Set up External ID](doc:1771100952291330).
4. Use the recommended event payload format.

#### `ad` parameters
Use the `ad` parameters to share information about the advertiser's website with Events API 2.0. 

| Field | Data Type | Description |
|---|---|---|
| campaign_id | string | The TikTok campaign ID associated with the touchpoint, typically parsed from the landing URL or deeplink. |
| ad_id | string | The TikTok ad group ID associated with the touchpoint, typically parsed from the landing URL or deeplink. |
| creative_id | string | The TikTok ad ID associated with the touchpoint, typically parsed from the landing URL or deeplink. |
| attribution_provider | string | Attribution provider. |
| attribution_share | float | Attribution share score. ⏎ A score provided by you per conversion, representing the portion of credit TikTok should receive for the conversion. A greater value indicates a larger credit share for TikTok. ⏎ Examples: • 0.0: No credit. • 0.5: Partial credit. • 1.0: Full credit. |
| attribution_value | float | The portion of the conversion's ROAS that your attribution system assigns to this TikTok touchpoint. ⏎ Typical usage: multiply the conversion value by the touchpoint's credit share (`attribution_share`) and pass the result here. ⏎ Example: an order worth $120 credited 25% to a TikTok touchpoint under a linear model yields `attribution_value = 30.0` for that event. |
| attribution_model | string | The attribution model that is used to attribute the event. ⏎ Examples: • `even_weight`: alias for evenly distributed credit. • `first_click`: full credit to the first click in the journey. • `first_touch`: full credit to the first touchpoint in the journey. • `last_click`: full credit to the last click in the journey. • `last_touch`: full credit to the last touchpoint in the journey. • `linear`: equal credit across every attributed touchpoint. |
| touchpoint_type | string | The type of TikTok touchpoint that received credit for this event. ⏎ Examples: • `click`: the user clicked a TikTok ad or a link that originated from a TikTok ad. • `view`: the user was served a TikTok ad impression without clicking. • `engaged_view`: the user watched a video ad for a qualifying duration (for example, 6 seconds or more) without clicking. • `engaged_click`: the user clicked and interacted with a rich media ad format (such as a Playable Ad). • `click_to_store`: the user clicked an ad that directed them straight to an app marketplace (for example, Apple App Store or Google Play). • `hybrid`: a mix of click and view signals contributed to the touchpoint. • `other`: any touchpoint that does not fit the categories above. |
| touchpoint_ts | integer | The time the TikTok touchpoint occurred, expressed as a Unix timestamp in seconds in the UTC+0 time zone. |
| touchpoint_url | string | The URL where the touchpoint was captured. ⏎ An example is the landing page URL that a user reached after clicking a TikTok ad. |
| attribution_window_hr_click | integer | The click-through attribution window, expressed in **hours**. ⏎ It defines the maximum interval between a TikTok click touchpoint and the conversion for which the click is still eligible to receive credit. ⏎ Examples: `1`, `24` (1 day), `168` (7 days), `720` (30 days). |
| attribution_window_hr_view | integer | The view-through attribution window, expressed in **hours**. ⏎ It defines the maximum interval between a TikTok view touchpoint (impression) and the conversion for which the view is still eligible to receive credit. ⏎ Examples: `1`, `24` (1 day), `168` (7 days) |
| attribution_method | string | The technical method used to associate the touchpoint with the conversion. ⏎ Examples: • `pixel`: matched through the TikTok pixel on the advertiser's website. • `PPS`: matched through Post-Purchase Survey. • `deeplink`: matched through a deeplink click identifier. • `modeled`: attribution produced by a statistical or ML model rather than a deterministic match. • `SKAN`: matched through Apple's SKAdNetwork framework. • `shop`: matched through a TikTok Shop signal. |
| decline_reason | string | The reason your system declined to assign attribution credit to TikTok for this event. ⏎ Examples: • `attributed_to_other_source`: another channel received the credit. • `organic`: no paid channel received credit; treated as an organic conversion. • `outside_attribution_window`: the TikTok touchpoint fell outside the click or view window. • `invalid_event`: the event failed a partner-side validation check. • `fraud_detected`: the touchpoint was flagged as fraudulent. • `duplicate_event`: the conversion was already counted in a prior report. • `low_confidence_match`: the touchpoint-to-conversion match did not meet the confidence threshold. • `missing_touchpoint`: no eligible TikTok touchpoint was found. • `missing_click_id`: the required TikTok click identifier was absent. • `privacy_threshold_filtered`: the event was filtered out by a privacy threshold. • `unsupported_signal`: the signal type is not supported by the attribution engine. • `other`: any other reason that does not fit the categories above. |
| utm_id | string | The unique identifier of the marketing campaign or UTM parameter set that produced the touchpoint. ⏎ It corresponds to the `utm_id` parameter in the landing URL. ⏎ Use this field to report the custom campaign identifier from your landing page URL. This is particularly useful if your internal tracking relies on custom UTM values rather than TikTok's default campaign IDs. ⏎ Example: `summer2026_launch`. |
| utm_source | string | The traffic source that referred the user to the landing page, as captured in the `utm_source` URL parameter. ⏎ It typically identifies the platform or property that hosted the ad. ⏎ Example: `tiktok`. |
| utm_medium | string | The marketing medium that delivered the traffic, as captured in the `utm_medium` URL parameter. ⏎ It identifies the category of the placement rather than the platform. ⏎ Examples: `cpc`, `paid_social`, `display`. |
| utm_campaign | string | The campaign name that produced the touchpoint, as captured in the `utm_campaign` URL parameter. ⏎ It is used to attribute performance to a specific marketing initiative within the traffic source. ⏎ Example: `summer2026_launch_us`. |
