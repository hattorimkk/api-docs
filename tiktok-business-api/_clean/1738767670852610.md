# Create rules
> Đường dẫn: API Reference > Automated Rules > Create rules
Use this endpoint to create automated rules.

> **Important:** 
> Currently, this endpoint is supported exclusively for direct advertisers. Automated rule notifications are routed directly to the developer's registered email address. Consequently, SaaS platforms and technology companies managing multiple advertisers cannot utilize this endpoint, as the system cannot route notifications to the individual managed advertisers.

## Request

**Endpoint** `https://business-api.tiktok.com/open_api/v1.3/optimizer/rule/create/`

**Method** POST

**Header**

| Field | Data Type | Description |
|---|---|---|
| Access-Token  **(Required)** | string | Authorized access token. For details, see [Authentication](doc:1738373164380162). |
| Content-Type  **(Required)** | string | Request message type ⏎ Allowed format: `"application/json"`. |

**Parameters**

| Field | Data Type | Description |
|---|---|---|
| advertiser_id  **(Required)** | string | Advertiser ID |
| rules | object[] | List of rules |
| ↳ apply_objects  **(Required)** | object[] | Objects that you want to apply the rules to. Objects can be campaigns, ad groups, or ads. |
| ↳↳ dimension  **(Required)** | string | Category of the object. Enum values: `CAMPAIGN`, `ADGROUP`, `AD`. |
| ↳↳ dimension_ids | string[] | IDs of the objects. |
| ↳↳ pre_condition_type  **(Required)** | string | Conditions to filter objects that you want to include.  • `SELECTED`: Only include those that are selected by IDs. • `ALL_ACTIVE_CAMPAIGN`: Select all active campaigns. • `ALL_ACTIVE_AD_GROUP`: Select all active ad groups.  • `ALL_ACTIVE_AD`: Select all active ads. • ` ALL_ACTIVE_AD_GROUP_UNDER_SELECTED`: Select all active ad groups under the selected campaign. • `ALL_ACTIVE_AD_UNDER_SELECTED`: Select all active ads under selected dimensions • `ALL_INACTIVE_CAMPAIGN`: Select all inactive campaigns.  • `ALL_INACTIVE_AD_GROUP`: Select all inactive ad groups • `ALL_INACTIVE_AD`: Select all inactive ads. • `ALL_INACTIVE_AD_GROUP_UNDER_SELECTED`: Select all inactive ad groups under the selected campaign. • `ALL_INACTIVE_AD_UNDER_SELECTED`: Select all inactive ads under the selected campaign or ad group (specified by `dimension` and `dimension_ids`) |
| ↳ conditions  **(Required)** | object[] | Conditions |
| ↳↳ subject_type  **(Required)** | string | Subjects that the condition will be based on. Enum values:  • `COST` • `DAILY_BUDGET_SPENDING_RATE` • `LIFETIME_BUDGET_SPENDING_RATE` • `IMPRESSION` • `CLICK` • `CONVERSION` • `CONVERSION_SKAN` • `CVR` • `CVR_SKAN` • `CPA` • `CPM` • `CPC` • `CTR` • `COST_PER_RESULT` • `RESULT` • `RESULT_RATE` • `BID_STRATEGY`: `values` must be one of these: `COST_CAP`, `BID_CAP`, `MAX_CONVERSION`, `LOWEST_COST`. • `OPTIMIZATION_GOAL`: `values`must be one of these: `CONVERT`, `CLICK`, `SHOW`, `REACH`, `INSTALL`, `IN_APP_EVENT`, `LEAD_GENERATION`, `TWO_SECOND_VIDEO_VIEW`, `SIX_SECOND_VIDEO_VIEW` • `OBJECTIVE`: `values`must be one of these: `TRAFFIC`, `APP_PROMOTION`, `WEB_CONVERSIONS`, `VIDEO_VIEWS`, `REACH`, `LEAD_GENERATION` • `NAME` • `DAYS_SINCE_CREATION`: `match_type` should be one of `GT`, `LT`, `BETWEEN`, `MATCH`. • `NO_CONDITION`: Be careful when setting a rule without any conditions to avoid any unintended changes. • When you use this value, you need to set `conditions` strictly to `["subject_type":"NO_CONDITION"]` without including any other conditions. Additionally, you need to set `pre_condition_type` to `SELECTED`, `ALL_ACTIVE_AD_UNDER_SELECTED`, `ALL_ACTIVE_AD_GROUP_UNDER_SELECTED`, `ALL_INACTIVE_AD_UNDER_SELECTED`, or `ALL_INACTIVE_AD_GROUP_UNDER_SELECTED`. • `ROAS_PURCHASE` • `ROAS_IMPRESSION_ADS` • `ROAS_PURCHASE_SKAN` • `ROAS_COMPLETE_PAYMENT` • `ROAS_PURCHASES_ONSITE` • `NOT_REAL_TIME_CPA` • `NOT_REAL_TIME_CONVERSION` • `NOT_REAL_TIME_CVR` |
| ↳↳ range_type | string | Time range for the condition. Enum values:  • `TODAY` • `YESTERDAY` • `PAST_THREE_DAYS` • `PAST_FIVE_DAYS` • `PAST_SEVEN_DAYS` • `LIFETIME` |
| ↳↳ match_type | string | Operator to connect a condition with a value. Enum values: `GT` (greater than), `LT` (less than), `BETWEEN`, `MATCH`. Only when `subject_type` is `NAME`, can below `match_type` be used: • `CONTAINS` • `NOT_CONTAINS` • `START_WITH` • `END_WITH` • `STRING_EQUAL` |
| ↳↳ values | string[] | Values for the condition. If `match_type` is `BETWEEN`, include two values in this array ⏎ **Note**: Verification rules for the `values` field vary with the `subject_type` you pass in. See Verification Rules for values for details. |
| ↳↳ calculation_type | string | The `subject_type` has to be `COST`. Set to `OF_EACH_OBJECT` by default if this field is not provided. • `ALL_OBJECTS` • `OF_EACH_OBJECT` |
| ↳ actions  **(Required)** | object[] | Actions to be taken when the condition is met. |
| ↳↳ subject_type  **(Required)** | string | Type of actions to take. Enum: `TURN_ON`, `TURN_OFF`, `MESSAGE`, `DAILY_BUDGET`, `LIFETIME_BUDGET`, `BID`. |
| ↳↳ action_type | string | Enum values: `INCREASE`, `DECREASE`, `ADJUST_TO`. |
| ↳↳ value_type | string | Enum values: `EXACT`, `PERCENT`. |
| ↳↳ value {+conditional} | object | The budget value. ⏎ Required when `subject_type`=`DAILY_BUDGET`, `LIFETIME_BUDGET` or `BID`. |
| ↳↳↳ value {+conditional} | float | The budget value you want to increase, decrease or adjust to. • If `action_type` =`INCREASE` or `DECREASE`, value range:[0.01, 1000000000000].  • If `action_type` =`ADJUST_TO`:  • when `dimension`=`CAMPAIGN`, value range: [50, 1000000000000]. • when `dimension`=`ADGROUP`,  value range: [20, 1000000000000]. |
| ↳↳↳ limit {+conditional} | float | The maximum budget cap (if `action_type` =`INCREASE`) or minimum budget ( if `action_type` =`DECREASE`). ⏎ Required when `action_type` =`INCREASE` or `DECREASE`. ⏎ • When `dimension`=`CAMPAIGN`, value range: [50, 1000000000000].  • When `dimension`=`ADGROUP`, value range: [20, 1000000000000]. ⏎ If `action_type`=`ADJUST_TO`, you don't need to pass in this field. |
| ↳↳ frequency_info | object | Frequency settings. It can be used when the action `subject_type` is `DAILY_BUDGET`, `LIFETIME_BUDGET`, or `BID`. |
| ↳↳↳ type | string | Enum values: •  `ONLY_ONCE` •  `ONCE_IN_24_H` •  `ONCE_IN_48_H` •  `ONCE_IN_1_W` •  `CUSTOM` |
| ↳↳↳ custom_frequency_type | string | Custom frequency type. Valid only when `type` is `CUSTOM`. Enum: •  `N_MINTUE_Y_TIMES` •  `N_HOUR_Y_TIMES` •  `N_DAY_Y_TIMES` |
| ↳↳↳ time | number | It is the `N` in `custom_frequency_type` |
| ↳↳↳ count | number | It is the `Y` in `custom_frequency_type` |
| ↳ notification  **(Required)** | object | Notification settings |
| ↳↳ notification_type  **(Required)** | string | Notification type you need. Enum values:  • `TASK_FINISH`: Notification will be sent when the task is finished. This option is only for `MESSAGE` subject type. • `ANY_CHANGES`: If the `subject_type` for the action is not `MESSAGE` but you still want to receive emails, use this option. • `NOT_NOTIFICATION`: No notifications are needed. |
| ↳↳ email_setting | object | Email notification settings |
| ↳↳↳ notification_period | string | Enum values: • `EVERY_TIME` • `TIME_SCHEDULE`: notifications will be sent together around a specified time. |
| ↳↳↳ email_exec_time | string[] | Required when `notification_period` is`TIME_SCHEDULE`. Notification email sent time. For example, "12:00". |
| ↳↳↳ no_result_notification | boolean | It will be set as false by default if not provided, meaning no notification will be sent if there is no result. |
| ↳↳↳ mute_option | string | This field can be used to mute or unmute email notification for the day. Enum values: • `MUTE` • `UNMUTE` |
| ↳ rule_exec_info  **(Required)** | object | Rule run settings. |
| ↳↳ exec_time_type  **(Required)** | string | When the rule will be run. Enum values:  • `PER_HALF_HOUR`: the rule will be run every half hour. • `CUSTOM`: the rule will be run at a customized time (specified in the `exec_time` field). • `HALF_HOUR_IN_SPECIFIC_TIME_PERIOD`: the rule will be run every 30 minutes during specified time range on specifed days during the week. • `SPECIFIC_TIME_ACCURATE_ONCE`: the rule will be run only once at a customized time (specified in the `exec_time` field). |
| ↳↳ exec_time | string | If `exec_time_type` is set to `CUSTOM` or `SPECIFIC_TIME_ACCURATE_ONCE`, use this field to specify the exact time when the rule will be run. ⏎ Format: ⏎ • "HH:MM" when `exec_time_type` is `CUSTOM`. For example: "12:00". • "YYYY-MM-DD HH:MM" when `exec_time_type` is `SPECIFIC_TIME_ACCURATE_ONCE`. For example: "2023-04-20 04:20".**Note**: If `exec_time_type` = `SPECIFIC_TIME_ACCURATE_ONCE`, the `exec_time` cannot exceed one year from the current time. |
| ↳↳ time_period_info | object[] | Valid when `exec_time_type` is `HALF_HOUR_IN_SPECIFIC_TIME_PERIOD`. It has `start_time`, `end_time`, `date_type` and `num` to specify the time period information. |
| ↳↳↳ num{+Conditional} | integers[] | Required when `date_type` is `WEEK` or `MONTH`. Each number in the list represents the day in the week or month. ⏎ • When `date_type` is `WEEK`, value range for this field is  [1, 7], meaning Monday to Sunday. • When `date_type` is `MONTH`, value range for this field is  [1, 28], meaning 1st day to the 28th day of the month. |
| ↳↳↳ start_time | string | Start time of this time period. For example, "12:00". |
| ↳↳↳ end_time | string | End time of this time period. For example, "12:00". |
| ↳↳↳ date_type | string | Type of date. Enum values: `DAY`, `WEEK`, `MONTH`. |
| ↳ tzone | string | User timezone. In create/update rules, it's used with `mute_option` in notification.email_setting. For acceptable timezone code, see [Time Zone](doc:1737586324313089). |
| ↳ name  **(Required)** | string | Name of the rule. |
| lang | string | Language of the error messages. Enum values: `ZH` (Simplified Chinese), `EN` (English)(default), `JA` (Japanese). |

### Example

```http
// curl
curl --location --request POST 'https://business-api.tiktok.com/open_api/v1.3/optimizer/rule/create/' \
--header 'Access-Token: {{Access-Token}}' \
--header 'Content-Type: application/json' \
--data '{
    "advertiser_id": "{{advertiser_id}}",
    "rules": [
        {
            "apply_objects": [
                {
                    "dimension": "CAMPAIGN",
                    "dimension_ids": [],
                    "pre_condition_type": "ALL_INACTIVE_CAMPAIGN"
                }
            ],
            "conditions": [
                {
                    "subject_type": "CLICK",
                    "range_type": "LIFETIME",
                    "match_type": "GT",
                    "values": [
                        "0"
                    ]
                }
            ],
            "actions": [
                {
                    "subject_type": "MESSAGE"
                }
            ],
            "notification": {
                "notification_type": "TASK_FINISH"
            },
            "rule_exec_info": {
                "exec_time_type": "CUSTOM",
                "exec_time": "12:00"
            },
            "name": "[API]Automated Rule-example"
        }
    ]
}'
```

### Verification Rules for `values`
Verification rules for the `values` field vary with the `subject_type` you pass in. Please specify the `values` field according to the rules. Otherwise, an error will occur. See the table below for verification rules in detail.

| subject_type | Verification rules for values |
|---|---|
| NAME | Length range: (0,512] |
| COST ⏎ CPA ⏎ NOT_REAL_TIME_CPA ⏎ CPM ⏎ CPC ⏎ COST_PER_RESULT | Precision: determined by the currency of your advertiser account(See [Currency-specific precision](doc:1772544628718594) for details.) ⏎ Value range: [0,100000000] |
| DAILY_BUDGET_SPENDING_RATE ⏎ LIFETIME_BUDGET_SPENDING_RATE ⏎ CVR ⏎ CVR_SKAN ⏎ NOT_REAL_TIME_CVR ⏎ CTR ⏎ RESULT_RATE | Precision: 0.01 ⏎ Value range: [0,100] |
| IMPRESSION ⏎ CLICK ⏎ CONVERSION ⏎ CONVERSION_SKAN ⏎ NOT_REAL_TIME_CONVERSION ⏎ RESULT | Precision: 1 ⏎ Value range: [0,10000000000] |
| ROAS_PURCHASE ⏎ ROAS_IMPRESSION_ADS ⏎ ROAS_PURCHASE_SKAN ⏎ ROAS_COMPLETE_PAYMENT ⏎ ROAS_PURCHASES_ONSITE | Precision: 0.01 ⏎ Value range: [0,100000] |
