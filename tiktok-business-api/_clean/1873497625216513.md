# How to connect a custom agent to TikTok for Business MCP Server
> Đường dẫn: TikTok for Business MCP Server > How to connect a custom agent to TikTok for Business MCP Server
If you are building a custom agent, you can connect it directly to the TikTok for Business MCP Server. This gives your agent direct, programmatic access to the TikTok Ads platform using standard Model Context Protocol (MCP) tool calls.

Because your custom agent operates independently, it must handle its own OAuth 2.0 authorization flow. This guide walks you through the complete lifecycle: from discovering the server configuration and registering your client application, to securing user consent via PKCE (Proof Key for Code Exchange) and executing your first MCP tool.

If you want to use an existing, MCP-compatible AI platform, see [How to connect a ready-made agent to TikTok for Business MCP Server](slug:how-to-connect-to-tiktok-for-business-mcp-server) instead.

> **Important:** 
> Each MCP server path issues its own tokens. A token obtained for one server path (for example, `tt-ads-mcp-layer`) is strictly scoped to that path and cannot be used to authenticate against a different path (for example, `tt-ads-mcp-flat`). If your agent connects to multiple server paths, you must complete a separate OAuth flow for each one.

# Core concepts
Before diving into the code, familiarize yourself with the terminology used in this flow:
- **Model Context Protocol (MCP)**: An open standard that allows clients to call external tools through a unified interface. TikTok for Business exposes its ads tools as an MCP server.
- **MCP server URL**: The endpoint your agent connects to (`https://business-api.tiktok.com/open_mcp/{server}`). Each URL issues and accepts its own tokens.
- **Dynamic Client Registration (DCR)**: A process that allows your agent to register itself and receive a `client_id` at runtime. This bypasses the need for manual, upfront registration.
- **PKCE (Proof Key for Code Exchange)**: A security protocol that prevents authorization code interception by generating a dynamic, one-time secret (`code_verifier` and `code_challenge`) for every login attempt.
- **Redirect URI:** The address the authorization server returns the user to, with the authorization code, after they approve access. It must be registered with your client.
- **Authorization code:** A one-time, short-lived code returned to your redirect URI. Your agent exchanges it for tokens.
- **MCP access token and refresh token:** The access token authenticates tool calls and is valid for 24 hours. The refresh token obtains a new access token and is valid for 30 days.
- **Bearer token**: An OAuth 2.0 access token where possession of the token itself is sufficient for access. It must be transmitted over a secure channel (HTTPS) and included in the HTTP request as `Authorization: Bearer `.
- **Developer app:** An application created in the TikTok for Business developer portal. It acts as the central hub for managing your integration's permission scopes, rate limits, and credentials.
- **API access token:** A long-term token obtained via the Marketing API authorization workflow. It does not expire unless explicitly revoked.

# Before you start
Confirm the following requirements before writing any code:
- **A TikTok for Business account.** The account authorizes the connection so your agent can act on your behalf. If you do not have one, [create a TikTok for Business account](slug:create-a-tiktok-for-business-account) first.
- **An OAuth 2.0 client with PKCE support.** Your agent must be able to generate a SHA-256 PKCE `code_verifier` and `code_challenge`, handle browser redirects, and securely store tokens.
- **A redirect URI you control.** The exact web address where users are redirected after they authorize. It must use `https://`, though `http://` is allowed for local testing (such as `localhost`, `127.0.0.1`, `::1`).

# Choose your server URL
TikTok for Business MCP Server offers two server URLs. Choose the one that matches your agent's context window and tool-loading strategy. You will use its `{server}` value in every endpoint throughout this guide.

| Server type | {server} value | When to use |
|---|---|---|
| Full Disclosure | `tt-ads-mcp-flat` | All around 400 tools load at connection time. Use it when your AI platform has a large context window and can handle the full tool library without performance degradation. ⏎ Explore the full tool library in [Available tools in TikTok for Business MCP Server](slug:available-tools-in-tiktok-for-business-mcp-server). ⏎ Recommended for Claude. |
| Progressive Disclosure | `tt-ads-mcp-layer` | Only around 40 core tools load initially; additional tools are discoverable on-demand. Use it for token-conscious setups or agents with limited context windows. |

# Connection flow overview
The connection lifecycle follows a standard OAuth 2.0 flow. Setup runs once per client application, authorization runs once per user, and token management keeps the connection alive.

The specific steps vary depending on whether you use an MCP access token or an API access token.

**Path 1: When using an MCP access token:**
- **Setup**
**1. Discover the configuration**: Fetch the OAuth endpoints dynamically.
**2. Register your agent**: Obtain your `client_id` via Dynamic Client Registration.

- **Authorization**
**3. Request user authorization**: Redirect the user to approve access using PKCE.
**4. Exchange the code for tokens**: Exchange the short-lived authorization code for an access token and a refresh token.

- **Usage & maintenance**
**5. Call MCP tools**: Execute advertising operations using your access token.
**6. Refresh the token**: Obtain a new access token before the current 24-hour token expires.
**7. Revoke the token** (Optional): Securely terminate the connection when it is no longer needed.

**Path 2: When using an API access token:**

- **Authorization**
**1. Get an API access token**: Obtain an API access token through the API authorization workflow.

- **Usage & maintenance**
**2. Call MCP tools**: Execute advertising operations using your access token.
**3 Revoke the token** (Optional): Securely terminate the connection when it is no longer needed.

# Steps
## Path 1: When using an MCP access token
### 1. Discover the OAuth configuration
Instead of hardcoding URLs, fetch the authorization server metadata dynamically using the [/open_mcp/{server}/oauth/.well-known/openid-configuration/](slug:get-authorization-server-metadata) endpoint. This ensures your agent automatically adapts if endpoint URLs change in the future.
> **Note:** 
> The code example belows uses `tt-ads-mcp-layer` as `{server}`. Substitute your chosen value wherever `{server}` appears.

```http
// curl
curl --location --request GET 'https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer/oauth/.well-known/openid-configuration'
```

The response will provide the exact URLs you need for registration, authorization, token exchange, and revocation.

```http
// curl
{
  "issuer": "https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer/oauth",
  "authorization_endpoint": "https://business-api.tiktok.com/portal/mcp-tt4b-authorize",
  "token_endpoint": "https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer/oauth/token",
  "registration_endpoint": "https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer/oauth/register",
  "revocation_endpoint": "https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer/oauth/revoke",
  "response_types_supported": ["code"],
  "grant_types_supported": ["authorization_code", "refresh_token"],
  "code_challenge_methods_supported": ["S256"],
  "token_endpoint_auth_methods_supported": ["none"],
  "scopes_supported": ["mcp:tt4b"]
}
```

(Optional) If your agent initiates from the MCP resource directly, you can call the [/.well-known/oauth-protected-resource/open_mcp/{server}/](slug:discover-authorization-servers) endpoint to discover the correct authorization server.

**Example**
> **Note:** 
> The code example below uses `tt-ads-mcp-layer` as `{server}`. Substitute your chosen value wherever `{server}` appears.

Request
```http
// curl
curl --location --request GET 'https://business-api.tiktok.com/.well-known/oauth-protected-resource/open_mcp/tt-ads-mcp-layer'
```

Response
```http
// curl
{
  "resource": "https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer",
  "authorization_servers": [
    "https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer/oauth"
  ],
  "scopes_supported": ["mcp:tt4b"],
  "bearer_methods_supported": ["header"]
}
```

### 2. Register your agent
Register your agent (client application) once with Dynamic Client Registration to obtain a `client_id` using the [/open_mcp/{server}/oauth/register/](slug:register-a-client-application) endpoint.

As a best practice, we recommend using a consistent `client_name` for each agent you build. A successful registration returns your `client_id`. You only need to register the agent once. Save this `client_id` and reuse it for all future authorization requests associated with this agent.

**Example**
> **Note:** 
> The code example below uses `tt-ads-mcp-layer` as `{server}`. Substitute your chosen value wherever `{server}` appears.

Request
```http
// curl
curl --location --request POST 'https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer/oauth/register' \
--header 'Content-Type: application/json' \
--data '{
    "client_name": "{{client_name}}",
    "redirect_uris": [
        "{{redirect_uri}}"
    ],
    "token_endpoint_auth_method": "none",
    "grant_types": [
        "authorization_code",
        "refresh_token"
    ],
    "response_types": [
        "code"
    ]
}'
```

Response
```http
// curl
{
    "client_id": "{{client_id}}",
    "client_id_issued_at": 1784928815,
    "grant_types": [
        "authorization_code",
        "refresh_token"
    ],
    "redirect_uris": [
        "{{redirect_uri}}"
    ],
    "response_types": [
        "code"
    ],
    "token_endpoint_auth_method": "none"
}
```

### 3. Request user authorization
To get user consent, you need to generate a PKCE challenge and redirect the user's browser to the TikTok for Business login page.

3.1 Generate the verifier: Create a `code_verifier` (a random, secure string between 43 and 128 characters).

3.2 Generate the challenge: Hash your `code_verifier` using SHA-256 and Base64-URL encode it to create your `code_challenge`.

3.3 Redirect the user: Open the authorization endpoint [/portal/mcp-tt4b-authorize/](slug:request-user-authorization) in the user's browser, appending your parameters:

**Example**
> **Note:** 
> The code example below uses `https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer` as `{resource}`. Substitute your chosen value wherever `{resource}` appears.

```http
// curl
https://business-api.tiktok.com/portal/mcp-tt4b-authorize?response_type=code&resource=https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer&client_id={{client_id}}&redirect_uri={{redirect_uri}}&scope=mcp:tt4b&code_challenge={{code_challenge}}&code_challenge_method=S256
```

The user signs in to TikTok for Business, reviews the requested permissions, and approves the request. Once the user approves the permissions, the server will redirect them back to your `redirect_uri` with a short-lived authorization code attached to the URL:

**Example**
```http
// curl
https://example.com/oauth/callback?code=AUTH_CODE
```

### 4. Exchange the authorization code for tokens
Exchange the authorization code for an access token and refresh token using the [/open_mcp/{server}/oauth/token/](slug:exchange-an-mcp-authorization-code-for-tokens) endpoint. To prove your agent's identity, you need to include the original, unhashed `code_verifier` you generated in Step 3.

A successful response returns an `access_token` (valid for 24 hours) and a `refresh_token` (valid for 30 days).

**Example**
> **Note:** 
> The code example below uses `tt-ads-mcp-layer` as `{server}`. Substitute your chosen value wherever `{server}` appears.

Request
```http
// curl
curl --location --request POST 'https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer/oauth/token' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'grant_type=authorization_code' \
--data-urlencode 'code={{code}}' \
--data-urlencode 'code_verifier={{code_verifier}}' \
--data-urlencode 'redirect_uri={{redirect_uri}}'
```

Response
```http
// curl
{
    "access_token": "{{access_token}}",
    "expires_in": 86399,
    "refresh_token": "{{refresh_token}}",
    "refresh_token_expires_in": 2591999,
    "scope": "mcp:tt4b",
    "token_type": "bearer"
}
```

With your access token in hand, you can now interact with the MCP server using the [/open_mcp/{server}/](slug:use-mcp-tools) endpoint.

#### Execute a tool
To execute a specific tool (for example, `advertiser_info_get`), use the `tools/call` method and pass the required arguments.

> **Note:** 
> Each tool is rate-limited to 6 queries per second (QPS) per TikTok for Business user. For example, you can call `smart_plus_ad_create` three times and `smart_plus_ad_update` three times within the same one-second window.
> The following example shows how you can use the `advertiser_info_get` tool to retrieve the details of an ad account.

**Example**
> **Note:** 
> The code example below uses `tt-ads-mcp-layer` as `{server}`. Substitute your chosen value wherever `{server}` appears.

Request
```http
// curl
curl --location --request POST 'https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer' \
--header 'Access-Token: {{Access-Token}}' \
--header 'Content-Type: application/json' \
--data '{
    "jsonrpc": "2.0",
    "id": {{id}},
    "method": "tools/call",
    "params": {
        "name": "advertiser_info_get",
        "arguments": {
            "advertiser_ids": [
                "{{advertiser_ids}}"
            ],
            "fields": [
                "name",
                "status",
                "currency",
                "timezone"
            ]

}'
```

### 6. Refresh the access token
Because access tokens expire after 24 hours, you need to use your refresh token to obtain a new one to keep the connection alive.

Send a request to the same [/open_mcp/{server}/oauth/token/](slug:refresh-an-mcp-access-token) endpoint. Send `grant_type=refresh_token` and the `refresh_token`. The response matches the Step 4 success response with a new `access_token`.

> **Important:** 
> User authorization remains valid for a 30-day window. Once the refresh token expires, you need to send the user back through the browser authorization flow (Step 3) to reauthorize the connection using the same TikTok for Business account.

**Example**
> **Note:** 
> The code example below uses `tt-ads-mcp-layer` as `{server}`. Substitute your chosen value wherever `{server}` appears.

Request
```http
// curl
curl --location --request POST 'https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer/oauth/token' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'grant_type=refresh_token' \
--data-urlencode 'refresh_token={{refresh_token}}'
```

Response
```http
// curl
{
    "access_token": "{{access_token}}",
    "expires_in": 86399,
    "refresh_token": "{{refresh_token}}",
    "refresh_token_expires_in": 2591941,
    "scope": "mcp:tt4b",
    "token_type": "bearer"
}
```

### 7. (Optional) Revoke the access token 
To end a connection, revoke a token with a request to the [/open_mcp/{server}/oauth/revoke/](slug:revoke-an-mcp-token) endpoint, passing the `token`.

**Example**
> **Note:** 
> The code example below uses `tt-ads-mcp-layer` as `{server}`. Substitute your chosen value wherever `{server}` appears.

Request
```http
// curl
curl --location --request POST 'https://business-api.tiktok.com/open_mcp/tt-ads-mcp-layer/oauth/revoke' \
--header 'Content-Type: application/x-www-form-urlencoded' \
--data-urlencode 'token={{token}}' \
--data-urlencode 'token_type_hint=access_token'
```

Response
```http
// curl
{
    "revoked": true
}
```

# Best practices & security rules
- **Strict redirect matching**: The `redirect_uri` used in the token exchange (Step 4) must be a 1:1 exact match with the URI used in the authorization request (Step 3).
- **Always use PKCE**: Use PKCE with the `S256` method for every authorization request.
- **Do not share tokens:** Tokens are bound to the specific MCP server path in the URL. Do not attempt to reuse tokens across different paths.
- **One-time use codes**: Authorization codes can only be used once. They cannot be redeemed again after they are consumed or expire.
- **Debugging**: Always treat the `error_description` field in error responses as your primary source of truth for troubleshooting failures.
